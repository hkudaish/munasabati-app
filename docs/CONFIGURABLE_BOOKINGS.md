# منظومة إعداد الخدمات والطلبات والحجوزات والتسويات

## التعريفات

**طلب الخدمة** سجل موثق لحاجة العميل: الخدمة والمنفذ والجهة المخولة والمدينة والموعد والمتطلبات والسعر والموافقات. قد يكون استعلام توفر أو طلب عرض سعر أو طلب موافقة أو طلب حجز مباشر. إنشاء الطلب لا يحجز المورد ولا يثبت التحصيل.

**عرض السعر** تسعير محدد المدة صادر من جهة مخولة، له تفاصيل أساس وإضافات ورسوم وخصم وضريبة وعربون ودفعات. سعر «يبدأ من» تقدير لا يتحول تلقائياً إلى سعر ملزم. قبول العرض يخص العميل المسجل صاحب الطلب.

**الحجز المؤكد** نتيجة تحقق التوفر الفعلي، وقبول السعر والشروط، وموافقة كل الجهات المطلوبة (باستثناء نموذج الحجز المباشر المصرح به)، ومطابقة الدفعة المطلوبة، ثم إجراء التأكيد الذي يحجز الموارد داخل معاملة واحدة. الحجز المباشر ذو العربون صفر يمكن تأكيده دون تحصيل، وتبقى الدفعات اللاحقة مستحقة.

**المنفذ** شخص أو مورد يؤدي الخدمة. **الجهة المديرة** حساب مخول بإدارة عرضه والتوفر والموافقة على حجزه. اسم فنان في قائمة التصنيفات لا يثبت تمثيله أو تفويض حجزه. لا تفعّل الإدارة ملف الشخص قبل التحقق من التفويض. يحجز ملف الفنان نفسه عبر الموردين ولا يسمح بحجزه بالتزامن.

**الطلب السابق** MultiVendorOrder يجمع عدة موردين في المسار السابق. يحتفظ النظام به وبصلاحياته وسجله. **ServiceRequest** يمثل خدمة/باقة بعقد سياسة مستقل؛ الخدمات المشتركة تضم جهات متعددة وحصص تسوية وموافقات منفصلة داخل هذا العقد. لا تجمع الطلبات المستقلة تلقائياً في فاتورة أو تحصيل واحد.

## الواجهات

- `/bookings/manage`: اختيار الخدمة والمنفذ والمدينة والتاريخ والمدة والباقة والإضافات والحقول المطلوبة، عرض السعر والشروط، إنشاء الطلب، متابعة الحالة والإجراءات والسجل والإشعارات. نفس الشاشة تعرض للإدارة جميع الطلبات وللجهة طلباتها وللعميل طلباته.
- `/bookings/settings`: إعداد خدمات المورد المعتمد. لا يغير المورد العمولة ولا يضيف حسابات مخولة خارج حسابه.
- `/system-admin/booking-settings`: واجهة مدير النظام، إضافة أنواع وسياسات أقسام وتصنيفات فرعية وأشخاص وخدمات مباشرة/خارجية/مشتركة. اختيار جميع الخدمات القائمة من قاعدة البيانات، لا قائمة خدمات ثابتة في الكود.
- روابط من الخدمة وصفحة الحجوزات وكتالوج المورد ولوحة مدير النظام.

## مراجعة الأقسام الحالية

كل سجل حالي في ServiceCategory وServiceSubcategory وServiceItem يظهر في إعدادات الإدارة؛ ليس مطلوباً إنشاء فرع برمجي لكل قسم. النموذج التالي إرشادي للاختيار الإداري، ولا يفرض أسعاراً أو نسباً افتراضية خاصة على الموردين:

| الأقسام/الخدمات | نموذج مناسب | موارد واشتراطات |
|---|---|---|
| القاعات والمواقع، القاعات والفنادق، قاعات الزواج | يوم/مدة/باقة، موافقة | الموقع، السعة، مواعيد الدخول والخروج وفترة التجهيز |
| تجهيز الزواج الكامل، الملكة، التخرج، الحفلات الخارجية | عرض سعر أو باقة، خدمة مشتركة | عدة جهات، الموافقات، نطاق التنفيذ، الموقع ومتطلبات الحفل |
| الضيافة والبوفيهات | حسب الضيوف/باقة | العدد النهائي والموقع والمدة والإضافات |
| الكوش والديكور والورد | باقة/عرض سعر | التجهيز والفك، الموقع، التنفيذ والتسليم |
| التصوير والتوثيق | ساعة/مدة/باقة | ملف المصور، ساعات التغطية، المخرجات |
| الفنان والفنانة والدي جي ومهندس الصوت والمنسق | توفر ثم عرض/موافقة | ملف شخص معتمد، جهة إدارة مخولة، تقويم الشخص المستقل |
| العروض والفنون والترفيه | مدة/باقة | الفرقة/المنفذ والموافقات والتجهيز |
| الصوت والإضاءة والشاشات | مدة/يوم/باقة | تقويم المورد والمعدات ومتطلبات الموقع |
| الزفات الجاهزة والمخصصة ومكتبات الفنانين والفنانات | ثابت/عرض سعر | شروط الاستخدام، العينة، متطلبات التخصيص؛ ربط فنان للمعاينة لا يعني أداءه حياً |

| الدعوات الرقمية | ثابت/باقة/عدد | بيانات المناسبة ومتطلبات المحتوى والتسليم |
| الكوادر والتنظيم والضيافة البشرية | ساعة/مدة/باقة | المنفذ، الورديات، جهة الإدارة |
| تأجير المستلزمات والجلسات | يوم/مدة/باقة | التوريد والاستلام والإرجاع وفترة التجهيز |
| متجر مستلزمات الحفلات | ثابت/إضافات بالوحدة/باقة | الكميات والتسليم؛ المخزون الكمي ليس بديلاً عن تقويم المورد الحصري |

الأقسام الإضافية المستقبلية تدخل نفس قواعد الإعداد. يحفظ النوع سياسة مشتركة، وتعدل سياسة القسم ثم الفرع ثم الخدمة بالترتيب. قواعد النطاق: `category:ID` و`subcategory:ID`. تعطيل قاعدة وراثة يلغي تطبيقها؛ تعطيل نوع/خدمة/شخص يمنع الطلب والتأكيد الجديدين. تبقى الطلبات القديمة قابلة للقراءة.

## السياسات والأسعار

جميع المبالغ في المحرك الجديد **هللات صحيحة**، والواجهة تعرض الريالات. أسعار الكتالوج القديم بالريال تحول إلى هللات عند حل إعداد الخدمة. النسب بوحدة 10000 = 100%. لا تؤخذ الأسعار أو الخصومات أو العمولة من بيانات العميل.

ثابت، يبدأ من (يلزم عرض)، ساعة (تقريب لأعلى لكل ساعة)، يوم (24 ساعة، تقريب لأعلى)، مدة بوحدة قابلة للضبط، عدد الضيوف، باقة مع مدة مستقلة. أسعار المدن تستبدل سعر الأساس للوحدة. الإضافات اختيارية: ثابتة أو وحدة أو ساعة أو ضيف، بكميات وحدود من الإعداد. الرسوم إلزامية منفصلة؛ الخصم يطبق على الأساس والإضافات، والضريبة على المجموع بعد الخصم مع الرسوم. العمولة تحسب من الصافي قبل الضريبة. ملف الإعداد التفصيلي يتيح كل هذه المفاتيح دون تعديل الكود.

العربون + نسب جدول الدفعات = 100%؛ لا يقبل النظام نسباً غير متطابقة. تحفظ نسخة Policy وPrice وشروط المنفذين والمديرين وحصصهم مع الطلب. تغيير سياسة لاحق لا يعيد تسعير الطلب القديم. عند تقديم عرض جديد تصفر موافقات الجهات ويعاد طلب قبول العميل. لا يمكن تغيير عرض مقبول ومدفوع من مسار عرض السعر.

## الحالات ودورة العمل

| الحالة | المعنى/الطرف المطلوب |
|---|---|
| REQUESTED | تعريف الطلب الجديد في سجل الإنشاء |
| AVAILABILITY_PENDING | الجهة المخولة تتحقق من التوفر |
| QUOTE_PENDING | الجهة تقدم عرضاً، دون افتراض سعر نهائي |
| CUSTOMER_APPROVAL_PENDING | العميل يقبل عرضاً لم تنته صلاحيته |
| APPROVAL_PENDING | انتظار موافقة كل الجهات المخولة |
| PAYMENT_PENDING | انتظار مطابقة الدفعة المطلوبة |
| READY_TO_CONFIRM | استيفاء الشروط؛ يلزم إجراء تأكيد نهائي وفحص التعارض |
| CONFIRMED | حجز الموارد فعلياً داخل المعاملة |
| IN_PROGRESS | التنفيذ بدأ عند الموعد بعد الدفعات المستحقة |
| COMPLETED | إثبات اكتمال التنفيذ؛ لا يعني تسوية المورد |
| CLOSED | اكتمال التحصيل والمطابقة وتسويات جميع الجهات |
| RESCHEDULE_REQUESTED | الموعد الأصلي محجوز؛ البديل ينتظر موافقة كل الجهات |
| CANCELLATION_REQUESTED | الإلغاء المدفوع/المؤكد يحتاج اعتماد الإدارة وتحديد الاسترداد |
| CANCELLED | إلغاء مع تحرير الموعد؛ الاسترداد يعرض منفصلاً ولا يفترض تنفيذه |
| DISPUTED | تجميد مسار التنفيذ والتسوية حتى حل إداري مسجل |
| REJECTED | رفض مسبب لطلب لم يحصّل |
| EXPIRED | إنهاء طلب غير مدفوع بعد مهلة صلاحيته |

الاستعلام يمر بمراجعة التوفر ثم عرض السعر؛ لا ينشئ حجزاً ضمنياً. يظهر انتهاء المهلة والتأخر آلياً في لوحة المتابعة. إنهاء الطلب المنتهي إجراء مسجل؛ لا يلغى طلب محصل تلقائياً. إعادة الجدولة تحفظ الموعد القديم حتى استكمال الموافقات وإعادة فحص وحجز البديل وتحرير القديم في نفس المعاملة. لا يغيّر طلب الجدولة المدة أو النطاق؛ اختلافها يحتاج عرضاً/طلباً جديداً.

## التوفر وسلامة التزامن

أيام العمل، ساعات العمل، أيام الحجب والإجازات، أقل مهلة، أقصى تقدم وفترة بين الحجوزات لكل خدمة ولكل شخص. يعاد فحص الأيام جميعها للخدمات التي تعبر منتصف الليل. التوقيت Asia/Riyadh. يوجد حجز حصري لكل مورد خدمة ولكل منفذ ومورد مرتبط؛ لا يوجد افتراض سعة معدات غير محدودة.

Serializable مع إعادة المحاولة وأقفال advisory مرتبة على الموارد قبل إدراج ServiceReservation. إعادة إرسال الإنشاء تستخدم مفتاحاً خاصاً بالمستخدم مع بصمة بياناته؛ تعديل الطلب يشترط version. يمنع التأكيد المتزامن لنفس الفنان حتى عبر متجرين. الحجوزات القديمة المقبولة تفحص عند تأكيد الجديد، والحجوزات الجديدة تفحص عند قبول القديم. لا تنشئ الطلبات غير المؤكدة حجزاً وهمياً. تلزم مراجعة محافظة للحجوزات التاريخية التي لا تملك وقتاً صالحاً للآلة.

## التسويات المالية

1. فصل حالة الخدمة عن التحصيل وعن الاسترداد وعن تسوية مقدم الخدمة. لا ينشئ قبول الحجز سجلاً مدفوعاً.
2. كل عملية PAYMENT/REFUND/PAYOUT: المبلغ بالهللة، العملة، مرجع تحويل فريد، الطلب، المستفيد، رابط إثبات، بيان، منشئ العملية، مراجع مختلف، وقت التسجيل والمراجعة، وحالة PENDING/VERIFIED/VOID.
3. لا يدخل التحويل في رصيد الطلب أو استحقاق التسوية قبل المراجعة المستقلة. لا تستطيع الجهة المقدمة أو العميل تعديل الرصيد. المرجع الفريد يمنع احتساب نفس التحويل مرتين. السجل المعتمد لا يعدّل من الواجهة.
4. مطابقة التحصيل مع مبلغ الطلب والدفعات، ومنع تجاوز الإجمالي أو تكرار التحصيل المعلق. العربون لا يساوي دفع كامل الخدمة.
5. استحقاق الاسترداد يحسب من المحصل وفق سياسة الطلب ووقت طلب الإلغاء، ويحفظ عند الطلب؛ استرداد كامل قبل مهلة الإلغاء المجاني، ونسبة محددة بعدها. يعتمد الإلغاء إداري، ثم يسجل استرداد منفذ فعلياً ويراجع مستقلاً. لا يسمح بتجاوز الاستحقاق أو برد مبلغ سوي للمورد دون مسار استرجاع ومطابقة منفصل.
6. التسوية متوقفة عند عدم اكتمال الخدمة (أو عدم اعتماد الإلغاء واستيفاء الاسترداد) أو نقص التحصيل أو النزاع أو عدم انتهاء hold period. صافي مستحق الجهات = الصافي قبل الضريبة − عمولة المنصة؛ الضريبة تبقى منفصلة في المطابقة ولا تحول ضمن صافي المورد في هذا النموذج التشغيلي.
7. الخدمات المشتركة: حصص موثقة مجموعها 10000، جميع الموافقات مطلوبة؛ توزع مستحقات الصافي حسب الحصص مع إسناد فرق التقريب للجهة الأخيرة. تمنع العمليات المعلقة والمعتمدة معاً تجاوز حصة الجهة أو الصافي الإجمالي.
بعد الإلغاء، يحسب صافي الرسوم المحتفظ بها من المحصل ناقص استحقاق الاسترداد، وتفصل ضريبتها بحسب نسبة السياسة ثم عمولتها وحصص الجهات. لا تحرر تسوية الرسوم حتى مطابقة كامل الاسترداد وانتهاء مهلة الحجز.

8. الإغلاق يشترط تطابق المحصل بعد الاستردادات مع الإجمالي (أو مطابقة استحقاق الاسترداد ورسوم الإلغاء عند الإلغاء)، وانتهاء العمليات المعلقة، وتسوية صافي الجهات كاملاً. التنفيذ المكتمل وحده لا يغلق الحساب.
9. الإثباتات البنكية روابط HTTPS خاصة تدير الإدارة صلاحية الوصول إليها؛ لا تعرض للعملاء والموردين. سجل العمليات ليس تكاملاً مصرفياً ولا دفتر أستاذ محاسبياً كاملاً ولا فاتورة ضريبية إلكترونية. تصدير المطابقات وربط دفتر الأستاذ والفواتير والبوابة يتطلب تكاملاً مالياً منفصلاً.

## الإشعارات والحدود التشغيلية

ServiceInbox: إنشاء وتحديث وتأكيد وإلغاء للعميل والجهات المخولة والإداريين النشطين، داخل نفس معاملة الحدث. تذكيرات الموعد والدفعات تحفظ بمواعيد الاستحقاق وتظهر داخل المنصة عند حلولها، مع القراءة. تمنع المفاتيح المركبة التكرار. عند إعادة الجدولة تحدث التذكيرات، وعند الإلغاء تزال المستقبلية. لا يدعي النظام إرسال SMS/WhatsApp/email؛ قنوات الدعوات القائمة لا تستخدم تلقائياً للحجوزات. تفعيل قناة خارجية للحجوزات يحتاج قوالب مناسبة ومزوداً وموثوقية تسليم وتفويض تشغيل.

نطاق التقويم الحالي حصري (سعة 1 لكل مورد/منفذ)، وليس مخزون معدات كمي أو تقسيم نوبات لطاقم مجهول. المكتبات والفيديو والصور السابقة تبقى مرتبطة بكتالوج المورد. يتطلب حجز فنان حي ملف شخص مفوضاً فعلياً. لا تُنشأ تفويضات أو حسابات أو أسعار حقيقية من أسماء الفنانين الافتراضية.
