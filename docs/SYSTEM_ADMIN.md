# مدير النظام والتحكم بالخدمات

لوحة مدير النظام مستقلة على `/system-admin` عن لوحة الإدارة التشغيلية `/admin`. دور قاعدة البيانات `SUPER_ADMIN` يملك صلاحيات إدارة النظام إضافة إلى صلاحيات الإدارة. الحساب ذو الدور `ADMIN` لا يستطيع دخول واجهات مدير النظام أو تغيير الخدمات أو أدوار الحسابات، ولو غيّر بيانات المتصفح. يظل حقل العرض `role: admin` متوافقاً مع الواجهة القديمة، ويضاف `hasSystemAccess` من جلسة الخادم لعرض مدخل لوحة مدير النظام.

## التحديث على قاعدة موجودة

بعد تطبيق ترحيل الدعوات السابق، نفذ مرة واحدة:

```sh
npx prisma db execute --schema prisma/schema.prisma --file prisma/sql/20261017-system-administration.sql
npx prisma db execute --schema prisma/schema.prisma --file prisma/sql/20261017-system-admin-setup.sql
npx prisma generate
```

الترحيلان إضافيان داخل معاملات، وقد نُفّذا على قاعدة التطوير الحالية. يضيف الأول حالة الحسابات وإعدادات الخدمات وسجل العمليات، ويضيف الثاني رموز التفعيل لمرة واحدة. لا يعاد تشغيلهما على قاعدة تم تحديثها. القاعدة الفارغة يمكن تهيئتها من مخطط Prisma الحالي. مولّد الزفة مخفي ومعطّل افتراضياً في الكود وفي ترحيل قاعدة البيانات.

## منح الصلاحية

للحسابات الموجودة التي لها كلمة مرور، يشغّل المشغّل المحلي الأمر التالي مع متغير البيئة `ACCOUNT_IDENTIFIER` المحدد:

```sh
node --env-file=.env scripts/provision-system-admin.cjs
```

لا يختار السكربت حساباً افتراضياً ولا ينشئ كلمة مرور. يسجل عملية المنح ويلغي جلسات الحساب القديمة، ثم يسجل صاحبه الدخول مجدداً.

للبريد الذي ليس له حساب بعد، يشغّل المشغّل المحلي الأمر التالي مع `SYSTEM_ADMIN_EMAIL` المحدد:

```sh
node --env-file=.env scripts/create-system-setup.cjs
```

يُخرج رابطاً خاصاً إلى `/system-setup#token=...` صالحاً لمدة 24 ساعة. يختار صاحب الرابط اسمه وجواله وكلمة مروره داخل التطبيق؛ يُنشأ حساب SUPER_ADMIN ويربط بالبريد المحدد ويُسجل دخوله. الرمز عشوائي من 32 بايت، وتحفظ تجزئته فقط في قاعدة البيانات. يستهلك داخل معاملة لا تسمح باستخدامه مرتين، حتى عند التزامن. إصدار رابط جديد للبريد نفسه يلغي القديم. الرابط لا يرسل بريداً تلقائياً ولا يسمح بإعادة تعيين كلمة مرور حساب موجود. الجزء الحساس من الرابط لا يُرسل في عنوان طلب الصفحة، وتمنع الصفحة الفهرسة وإرسال المرجع. لا تحفظ الروابط في المستودع أو تشاركها علناً.

## صلاحيات اللوحة

- الخدمات: إظهار المدخل أو إخفاؤه، وتشغيل الخدمة أو تعطيلها. الإخفاء وحده لا يمنع الوصول المباشر إلى خدمة مفعلة. التعطيل يمنع الصفحة ومسارات API المسجلة للخدمة. لوحة مدير النظام والمصادقة لا تدخلان ضمن قائمة الخدمات القابلة للتعطيل لتجنب فقدان الوصول.
- المستخدمون والإداريون: إنشاء حساب، تعديل الاسم والجوال والبريد والدور، إيقاف الحساب أو تفعيله، وإعادة تعيين كلمة المرور. لا تعرض تجزئات كلمات المرور. تغيير الدور أو الإيقاف أو إعادة تعيين كلمة المرور يلغي الجلسات القائمة. لا يمكن إيقاف أو سحب دور آخر مدير نظام نشط؛ تُنفذ عمليات الحسابات بمعاملة Serializable لمنع التعارض المتزامن.
- الموردون: عرض الملفات المسجلة، تعديل اسم المنشأة وحالة المراجعة/النشاط/الإيقاف والتوثيق. ملفات المنشآت الجديدة تأتي من تسجيل الموردين. لا يُحذف المورد أو حجوزاته عند إيقافه. يتوقف ظهور المورد الموقوف في الكتالوج العام، كما يُستبعد صاحب الحساب الموقوف. تستمر الإدارة المصرح لها في رؤية الملفات للمراجعة.
- سجل العمليات: آخر تغييرات الخدمات والحسابات والموردين، مع المنفذ والهدف والوقت. لا توجد واجهة لتعديل السجل أو حذفه، ولا تُسجل كلمات المرور أو رموز التفعيل أو مفاتيح القنوات فيه.

تعريف الخدمات ومداخلها في `src/lib/system/feature-catalog.ts`. تضيف الخدمة الجديدة تعريفاً ومساراتها وحماية الخادم المناسبة، ولا تُنشئ الواجهة تنفيذاً غير موجود. الصفحات المفتوحة تحدث الأعلام والكتالوج كل نحو 10 ثوانٍ وعند العودة للنافذة، وتتحقق API من حالة الخدمة وقت الطلب. أخطاء قراءة الأعلام توقف الوصول بدلاً من تفعيل خدمات مجهولة الحالة.

## مولّد الزفة

أزيلت آلية توليد النص من كود المتصفح ونقلت إلى `/api/zaffah/generate`، المحمي بعلم المولّد وعلم المكتبة معاً. المكتبة تبقى تعمل مع إخفاء المولّد وتعطيله. عند إعادة تفعيله، يُستخدم منطق القوالب النصية السابق؛ لم تتم إضافة مزود ذكاء اصطناعي خارجي في هذا التحديث. التحكم بالخدمة لا يغيّر هذا القيد.
