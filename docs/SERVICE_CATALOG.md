# التصنيفات الفرعية والفنانون ومكتبات الموردين

أضيفت تصنيفات فرعية وقوائم فنانين فعلية في PostgreSQL. اختيار اسم في الخطة لا ينشئ حجزاً؛ الحجز يرتبط بخدمة منشورة أضافها مورد معتمد، ويمر بمحرك الطلبات الحالي ومراجعة التوفر.

## الاستخدام

- `/plan`: في خطوة الخدمات، فعّل القسم ثم اختر التصنيفات الفرعية والفنان المفضل. تظهر الاختيارات في المراجعة وتُحفظ ضمن المناسبة وتظهر بعد إعادة تحميل مساحة العمل.
- `/artists`: استعراض الخدمات الفرعية والاختيار من الفنانين والفنانات. الخدمات المعروضة تأتي من قاعدة البيانات وتراعي المدينة وإتاحة المورد والتصنيف. افتح «التفاصيل وطلب الحجز» لإضافة الخدمة إلى السلة وإرسال الطلب.
- `/zaffah#supplier-library`: مكتبات الموردين، عينات الزفات المرخصة، اختيار الفنان أو الفنانة، وروابط مكتبات المحلات الخارجية.
- `/vendor/catalog`: للمورد صاحب المتجر فقط؛ إضافة وتعديل الخدمات، ربطها بتصنيف فرعي وفنان، حفظ المسودات وإيقاف النشر، وإضافة معرض المحل ورابط مكتبته.
- `/system-admin/catalog`: لمدير النظام؛ إضافة وتعديل وترتيب وتفعيل وتعطيل التصنيفات الفرعية والفنانين. لا يمكن نقل تصنيف أو فنان مرتبط بخدمات إلى نوع آخر يفسد الارتباطات.

## البيانات الأولية

13 تصنيفاً فرعياً:

- تنظيم المناسبات: تجهيز الزواج كاملاً، الملكة وعقد القران، التخرج، والحفلات الخارجية.
- القاعات: حجز قاعات زواج.
- الفنون والترفيه: حجز فنان، حجز فنانة، دي جي، ومهندس صوت.
- الزفات: جاهزة، مخصصة بالأسماء، زفات الفنانين، وزفات الفنانات.

قائمة الفنانين: محمد عبده، عبدالمجيد عبدالله، ماجد المهندس، راشد الماجد، فؤاد عبدالواحد، عايض، فهد الكبيسي، وليد الشامي، دحوم، برهان، سلطان خليفة، راشد الفارس، جابر الكاسر، إبراهيم الحكمي، علوي الدرب، محمد الناصر.

قائمة الفنانات: أصالة، أحلام، أميمة، رولان، زينة عماد، نوال الكويتية.

هذه أسماء للتصنيف والاختيار، وليست تأكيداً بأن المنصة أو أي مورد يمثّل أصحابها. لم تُنشأ عروض أسعار أو مواعيد أو حسابات موردين وهمية، ولم تُنسخ تسجيلات صوتية. يؤكد المورد صلاحية تقديم خدمة الفنان وحقوق نشر العينات والوسائط قبل حفظها وفق القواعد المحددة على الخادم.

## الصور والفيديو والصوت

يحفظ التطبيق روابط HTTPS والبيانات الوصفية. يستطيع المورد إضافة ما يصل إلى 20 رابط صورة و20 رابط فيديو للمحل أو للخدمة، ورابط مكتبة خارجية، ورابط عينة صوتية. الصور تظهر في معرض المحل، والفيديوهات المباشرة تعمل عبر مشغل المتصفح، وعينات الزفات عبر مشغل صوتي مع التحميل عند الطلب.

روابط الفيديو مخصصة لملفات MP4/WebM المباشرة؛ رابط موقع أو قناة يوضع في حقل المكتبة الخارجية. **رفع الملفات من الجهاز إلى Object Storage غير مضاف في هذا التغيير**؛ يجب استضافة الملفات المرخصة لدى المورد ثم إدخال روابطها. صلاحية الرابط التقنية لا تثبت حقوق المحتوى، ولا يتحقق الخادم من وجود الملف عبر تنزيله.

## قاعدة البيانات والنشر

الترحيل `netlify/database/migrations/202610180001_service_catalog.sql` إضافي: يحفظ الموردين والخدمات والمناسبات الموجودة، ويضيف `ServiceSubcategory` و`CatalogArtist` وحقول الوسائط والنشر والاختيارات. إدراج الأقسام والأسماء الأولية يستخدم `ON CONFLICT DO NOTHING` للحفاظ على أسماء الأقسام المخصصة. سجلات الخدمات القائمة تظل منشورة، واختيارات المناسبات القديمة تبدأ بقائمة فارغة.

في Netlify يطبّق ناشر قاعدة البيانات الترحيل داخل معاملته. لقواعد البيانات المحلية القائمة، يُطبّق الملف التالي **مرة واحدة**:

```bash
npx prisma db execute --file prisma/sql/20261018-service-catalog.sql --schema prisma/schema.prisma
npx prisma generate
```

لتهيئة القوائم في قاعدة جديدة بعد إنشاء المخطط، تستخدم `seed-service-catalog.cjs`، واستدعاؤها مدمج في تهيئة الجغرافيا وتهيئة التطبيق. لا تعيد التهيئة ضبط إعدادات الأسماء أو تفعيلها.

## واجهات API

| الواجهة | الوظيفة |
| --- | --- |
| `GET /api/catalog/options` | التصنيفات الفرعية والفنانون المفعّلون |
| `GET /api/catalog/services` | الخدمات المنشورة، مع بيانات الفنان والتصنيف والعينات |
| `GET /api/vendor/catalog` | المتجر وخدمات المورد صاحب الجلسة فقط |
| `POST /api/vendor/catalog` | إضافة/تعديل خدمة؛ `action: media` لمعرض المتجر؛ `action: unpublish` لإيقاف نشر خدمة |
| `GET/POST /api/system-admin/catalog` | إدارة القوائم بواسطة مدير النظام |
| `POST /api/occasions` و`PATCH /api/occasions/{id}` | حفظ `serviceSelections: [{ categoryId, subcategoryIds, artistIds }]` بعد فحص الانتماء والتفعيل |

الأذونات والروابط وارتباط الفنان بجنس التصنيف وملكية الخدمة تُفحص على الخادم. المسودات لا تظهر في الفهرس العام أو لقطة التغطية، ولا يمكن شراؤها. تعطيل فنان أو تصنيف فرعي يخفي خدماته من الفهرس ويمنع إنشاء طلب جديد لها، مع الحفاظ على تاريخ الطلبات القائمة. يُحفظ اسم الفنان ضمن عنوان عنصر الطلب كصورة من بيانات الطلب وقت الإنشاء.

## التحقق

```bash
npm run test:service-catalog-migration
npm run test:service-catalog
npm run test:commerce
npm run test:geo-engine
npm run test:invitations
npm run build
```

اختبارات الترحيل والتكامل تستخدم مخططات PostgreSQL مؤقتة منفصلة ولا تغيّر بيانات العملاء أو إعدادات التغطية الحقيقية. لتشغيل فحص Chrome/Edge المرئي على Windows مع اختبارات التكامل:

```powershell
$env:RUN_CATALOG_BROWSER = '1'
npm run test:service-catalog
```

يشمل فحص المتصفح اختيار تصنيف تجهيز الزواج وفنان في المعالج، حفظ المناسبة وإعادة تحميلها، اكتشاف خدمة الفنان، مدخل الحجز، وصفحة المورد، ومقاسات الجوال والحاسب. لقطات التحقق محلية داخل `.geo-test-artifacts` ولا تُنشر مع التطبيق.

الدفع الإلكتروني ورفع الملفات المباشر وتوثيق تمثيل الفنان عبر طرف خارجي تظل بحاجة إلى تكاملات مستقلة. تقديم الطلب لا يساوي حجزاً أو دفعاً مؤكداً.

اجتازت اختبارات الترحيل والتكامل والفحص المرئي، واختبارات محرك الطلبات والدعوات والتغطية، وبناء الإنتاج. بقيت تحذيرات تحسين الصور وتحذير قديم في شاشة الاستقبال ضمن فحص المشروع العام؛ فحص الملفات الجديدة لم يسجل أخطاء.
